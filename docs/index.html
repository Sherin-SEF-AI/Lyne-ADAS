What's new in v2.0

Accuracy first.

Public feedback on v1 was clear: distance came only from bounding-box size, so detector jitter produced false collision warnings. v2 rebuilds the perception-to-alert chain around physics, statistics and multiple independent cues.

v1

Range guessed from box width alone. A few pixels of jitter swung distance by metres, TTC flickered, and SUVs or pickups looked closer than they were.

v2

Range is fused from ground-plane geometry and learned width priors, filtered per object with an inverse-depth Kalman filter, and an alert fires only when closing is statistically significant.

Measured in replayed drives

JVM simulation tests project vehicles through a pinhole camera with realistic detector jitter (1.3 px per box edge at 256 px input), 5% missed detections and road bounce, then run the v1 and v2 pipelines side by side. Run them yourself with ./gradlew :app:testDebugUnitTest.

01 / RANGE

Multi-cue range estimation

Ground-plane geometry (camera height + horizon from the phone's gravity sensor) is fused with object-width priors by inverse variance. Each vehicle's true width is learned as it approaches, so wide SUVs and pickups are no longer misjudged.

02 / TRACKING

Per-object Kalman filter

Every track carries a range + closing-speed state with outlier gating. Distance stays smooth and the HUD shows a live ± uncertainty instead of a falsely precise number.

03 / TTC

Robust time-to-collision

A least-squares fit of log box scale over a ~1 s window is fused with Kalman range-rate TTC. Warnings require closing that is statistically significant, not a single noisy frame.

04 / GUARDS

False-alarm guards

  • Physical plausibility: closing speed can't exceed own speed
  • Minimum own speed before arming
  • Time-based persistence with hysteresis
  • Track maturity checks
  • One event per incident, not per frame
05 / PATH

Metric ego-path corridor

The danger zone is a metric corridor curved by gyro yaw-rate, following the road through bends. Cars parked at the roadside no longer trigger warnings.

06 / CALIBRATION

Auto-calibration

IMU mount pitch/roll plus online camera-height self-calibration from traffic statistics. A guided wizard with a level indicator and vehicle-type presets walks you through setup.

How it works

From photons to warnings, on-device.

Every frame flows through a single, allocation-free pipeline. Sensors (gravity, gyro, GPS) feed the geometry and risk stages alongside the camera.

  1. 01CameraFrames copied into a reused, preallocated buffer
  2. 02DetectorYOLOv8n INT8 + TwinLiteNet + GTSRB classifier
  3. 03Tracker + KalmanAssociations, outlier gating, range & closing-speed state
  4. 04Range fusionGround-plane geometry ⊕ learned width priors, inverse variance
  5. 05Risk logicFused TTC, ego-path corridor, plausibility & persistence
  6. 06Alerts / HUDVisual, audio & voice; dashcam clip; trip log
ModelsYOLOv8n INT8 (COCO), TwinLiteNet drivable area, GTSRB MobileNetV3 INT8. All LiteRT / TFLite, all on-device.
Real-time disciplineZero per-frame allocation and a single inference thread with drop-on-busy, so latency never piles up.
Delegate fallbackMeasured at runtime: NNAPI → GPU → XNNPACK. The fastest path that actually works on your device wins.

Safety

An aid, never a driver.

  • Warning-only. Lyne ADAS never steers, brakes or controls the vehicle in any way.
  • Estimates, not measurements. Distance, speed and TTC are derived from a phone camera and sensors and carry uncertainty, shown as ± on the HUD.
  • Not a certified safety system. It may miss hazards or warn late. Always drive attentively and obey local laws.
  • Mount it safely. Secure the phone so it doesn't obstruct your view or airbags, and set it up before you drive.

Open source. On-device. Free.
